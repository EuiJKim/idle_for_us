# Blade Idle 1.82.0 밸런스 분석 (2026-10-17)

분석 대상: `Blade+Idle_1.82.0_APKPure.xapk` (1.47GB, com.mobirix.mbbi)
목적: 성장 공식·수치표·콘텐츠 구성 파악 → 무협 회귀 게임 밸런스에 반영
**원작 그림·코드·텍스트는 가져오지 않음. 숫자 구조만 참고.**

## 어떻게 뽑았나

- XAPK 구성: 본체 38.9MB + 에셋 1,276MB + 네이티브 83.5MB
- Unity **IL2CPP** 빌드 (`assets/bin/Data/Managed/`가 비어 있음 = C#이 네이티브로 컴파일됨)
- 그런데 **밸런스 테이블이 평문 SQLite로 들어 있었음**: `assets/Test.db` (32.4MB)
  → IL2CPP 디컴파일(Ghidra/IDA) 없이 수치 전부 확보
- 테이블 2개: `StageTable` 24,924행 / `TicketTable` 16행

## 핵심 공식 (역산 결과)

| 항목 | 스테이지당 증가율 | 비고 |
|---|---|---|
| 적 ATK | **×1.02 (+2%)** | 후반 전 구간 일정 |
| 적 HP | **×1.01 (+1%)** | ATK보다 느림 |
| 권장 관통력 | ×1.003 (+0.3%) | 진행 게이트 |
| 반복 보상 | 거의 고정 | 값은 보상 ID (실수치 아님) |

**ATK가 HP보다 2배 빨리 오른다** — 플레이어가 "맞아 죽는" 쪽으로 압박을 주는 설계.
적 HP는 10^184, ATK는 10^210까지 감 (챕터 399 기준). 전형적 지수 인플레이션.

## 진행 게이트는 전투력이 아니라 '관통력(Penetration)'

- `recommendcondition1`이 메인 스테이지 **19,701개 전부 `Penetration`**
- 권장값: 27,000 (챕터15) → 3,305,000 (챕터399). 약 122배, **선형에 가까움**
- 적 체력은 10^184배 뛰는데 요구 스탯은 122배 → 데미지는 장비/스킬로 알아서 따라오고,
  **진행 여부는 관통력 하나로 통제**. 성장 축을 둘로 쪼갠 구조.

## 우리 무협 게임에 반영할 것

1. **스테이지당 증가율**: 적 ATK ×1.02 / HP ×1.01 를 기준선으로. (지금 우리는 80관문 회귀라 구간이 짧으니 ×1.05~1.08 정도로 압축 적용 검토)
2. **초반 15관문은 적 ATK 고정**, HP만 올리기 — 초반 이탈 방지
3. **한 판 47초** 고정 템포 — 우리도 관문당 목표 시간을 상수로 두고 역산
4. **진행 게이트를 별도 스탯으로**: Blade Idle의 관통력 = 우리 게임의 **경지(境地)**.
   데미지는 무공·병기로 자유롭게 키우되, 관문 진입은 경지로 막는 구조가 이미 우리 설계와 맞음
5. **지역 티어 재활용**: 8지역 × (일반/혈사/마교) 티어로 늘리면 에셋 추가 없이 구간 3배
6. 적 ATK가 HP보다 빨리 오르는 비대칭 — 체력 관리 긴장감 유지
