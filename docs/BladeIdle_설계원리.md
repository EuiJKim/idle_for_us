# Blade Idle 설계 원리 — 공략글에서 읽어낸 것 (2026-10-17)

> 출처: 네이버 게임 라운지 블루데이님 공략 2편
> ① "게임의 전체적인 육성 흐름" ② "온라인/오프라인 비교와 등반 타이밍"
> APK 수치 분석([BladeIdle_분석.md](BladeIdle_분석.md), [BladeIdle_진행구조.md](BladeIdle_진행구조.md))이
> "어떻게 만들었나"였다면, 이 문서는 **"플레이어가 왜 계속하나"**다.

## 1. 해금이 스테이지에 못 박혀 있고, 어느 지점에서 끝난다 ★

```
 2-25  특별 무료 패키지(2만 다이아)
 3-20  펫 던전
 8-20  문양 던전
 8-25  길드
 8-50  PvP · 도플갱어
11-25  매직 장신구 상자 드랍
13-50  레어 장신구 상자
15-50  레이드 1단계            ← 매일 티켓 2장 구매 가능
17-50  영웅 장신구 상자
20-50  레이드 2단계            ← 갓 피규어
21-25  1등급 영웅 장신구 상자  ← 갓 장신구 선택상자 0.5% 드랍 시작
21-50  전설 장신구 상자
25-25  신화 장신구 상자
25-50  레이드 3단계
───── 이후 골드·경험치·다이아 소폭 상승 외에 새 보상 없음 ─────
```

**해금은 전부 챕터의 20·25·50번 스테이지에 몰려 있다.**
DB에서 찾은 난이도 벽(25·50번에서 ×1.39)과 **정확히 같은 자리**다.

> 벽 = 보상 해금 지점. 벽을 넘으면 새 콘텐츠가 열린다.
> 턱이 있으니 "넘자"가 되고, 넘으면 실제로 뭔가 열린다.

그리고 **25-50에서 보상 테이블이 끝난다.** 399챕터 중 25챕터, 전체의 6%.
그 뒤 374챕터는 같은 보상이 수치만 커진다.
공략의 결론이 "21-25까지는 무리해서라도 빨리 올라가라"인 이유가 이것이다.

## 2. 갖고만 있어도 세지는 것들 (보유 효과)

| 요소 | 방식 | 규모 |
|---|---|---|
| 코스튬 | **장착 안 해도** 보유 효과 | 총 27.5만 다이아 → 코어공격력 +210%, 골드 +30%, 경험치 +20% 등 |
| 유물 | 60레벨 MAX | 총 60만 다이아 → 공격력 +1500%, 생명력 +800%, 관통 +2000, 치확 +20%, 치뎀 +200%, 최종공격력 +100%, **몬스터 생명력 -30%** |
| 피규어 | 등급별 1개씩 보유 | **공격력 ×14.78, 생명력 ×6.13, 방어력 ×4** |

피규어 한 줄이 전부다. 모든 등급을 하나씩 "갖기만" 해도 공격력이 14배가 된다.
장착 슬롯 경쟁이 없으니 **수집 = 성장**이고, 뽑기를 돌릴 이유가 영구히 생긴다.

**세트 조건부 보유 효과**도 있다 — 무기 4슬롯이 전부 신화 이상이면
치명타·슈퍼치명타 확률 보유 효과가 켜진다. 그래서 "좋은 옵션"보다
"일단 신화 4줄 채우기"가 먼저다.

## 3. 끝이 보이는 육성 라인

유물은 60레벨 MAX에 도달하면 **뽑기 풀에서 빠진다.** 전부 MAX면 뽑기 자체가 막힌다.
→ 무한 뽑기가 아니라 "언젠가 끝난다"가 눈에 보인다.

## 4. 아꼈다 쓰는 자원 — 공략이 존재하는 이유

| 자원 | 지금 쓰면 | 아꼈다 쓰면 |
|---|---|---|
| 레이드 티켓 | 1단계: 신화 피규어까지 | 20-50의 2단계: **갓 피규어** |
| 펫 소탕권 | 지금 클리어한 등급까지만 | 터틀(전설 1번) 클리어 후: 전설 조각 |
| PvP 입장권 | 낮은 등수 | 스펙 오른 뒤 몰아 쓰면 적은 표로 높은 승점 |
| 강화석 | 낮은 등급 무기에 낭비 | 20챕터까지 극심하게 부족 |
| 옵션석 | 갓4·3·2에 좋은 옵션 | 갓1 4슬롯 열린 뒤 한 번에 |

**"지금 쓰면 손해, 나중에 쓰면 이득"인 자원이 다섯 개 이상.**
이게 플레이어가 고민할 거리를 만들고, 공략이 읽힐 이유를 만든다.

## 5. 곱연산 3단 치명타

치명타 → 슈퍼치명타 → 하이퍼치명타. **전부 곱연산.**
그래서 슈치확 100%가 돼도 치뎀·슈치뎀·하치뎀을 다 올려야 한다.

골드 스탯 추천 순서: `치확 MAX → 슈치확 MAX → 치뎀 1000 → 슈치뎀 1000 → 공 10000`

## 6. 방치 보상이 두 갈래

| | 온라인(절전모드) | 오프라인 |
|---|---|---|
| 골드·경험치 | 기준 | **-30%** |
| 변동폭 | 크다(랜덤) | 작다(안정) |
| 상자·장신구·스킬북 | 거의 같음 | 거의 같음 |

클리어 18초 이상이면 둘이 비슷해진다. 그래서 **"클리어 타임이 늘어나도 위로 올라가라"**가 성립한다.

나머지(해금 개수, 보상 테이블이 끝나는 비율)는 이미 비슷하다.

## 8. 적용 (2026-10-17, v0.5)

### ① 난이도를 톱니로

```js
WALL_CYCLE = 10          // 10관문이 한 주기 — 지역이 바뀌는 자리와 같다
WALL_SHARE = 0.4         // 벽이 주기 성장의 40%를 혼자 먹는다(로그 기준)
DECAY = 0.64             // 주기 안에서 증가율이 이만큼까지 떨어진다
```

결과:

| 관문 | 이번 관문 배수 | 예전 공식 대비 |
|---|---|---|
| 2 | ×1.130 | 0.966 |
| 5 | ×1.110 | 0.840 |
| 9 | ×1.085 | **0.643** (벽 직전이 제일 수월하다) |
| **10** | **×1.874** | 1.030 ← 벽 |
| 11 | ×1.136 | **1.0000** (예전과 정확히 일치) |

**주기 전체 배수를 예전 ×1.17^10과 똑같이 맞췄다.** 그래서 10관문 경계마다
예전 곡선과 다시 만난다. 총량은 하나도 안 변하고 모양만 톱니가 됐다.

적 공격력도 같은 모양이고 HP보다 조금 더 가파르다(1.19 vs 1.17). 보상은 톱니로 만들지
않았다 — 벽에서 보상까지 튀면 벽 앞에 주차하는 게 이득이 되어버린다.

### ② 해금을 전부 벽 자리로

| 관문 | 열리는 것 |
|---|---|
| 10 | 무공 〈혈마해방〉 |
| 20 | 비경 〈흑도 전장〉 |
| 30 | 무공 〈운기조식〉 |
| 40 | 비경 〈한철 광산〉 |
| 50 | 무공 〈뇌정검〉 |
| 60 | 비경 〈영수 계곡〉 |
| 70 | 무공 〈질풍보〉 |
| 80 | 비경 〈고수의 동부〉 |
| 90 | 무공 〈천금수〉 |
| 100 | 무공 〈빙백신장〉 |
| 110 | 무공 〈만검귀종〉 |

**11개 벽에 빈자리가 없다.** 비경 난이도는 예전 기준(`base`)을 그대로 쓴다 —
개방 관문만 옮기고 난이도까지 밀면 보상이 뒤집힌다.

### ③ 화면에 벽을 보여준다

벽이 안 보이면 그냥 난이도 스파이크다. 세 가지를 넣었다.

- 상단에 `30관문까지 10 — 무공 〈운기조식〉` (다음 해금까지 남은 관문)
- 벽 관문에서는 지역 줄 앞에 `관문지기` + 붉은색
- `stageJump(s)`로 이번 관문이 몇 배 세졌는지 꺼내 쓸 수 있게 해뒀다

검증: `node tests/sim.mjs` 12시간 310~316관문 (적용 전 313).
초반은 0.25시간에 59관문으로 빨라졌다(적용 전 47) — 벽 직전이 수월해진 효과다.

## 9. 적용 ③ 보유 효과 — 병기보 (2026-10-17, v0.6)

### 있던 구멍

보유 효과(`EQUIP_TYPES.own`)는 이미 있었다. 문제는 **지금 가진 개수** 기준이었다는 것이다.

```js
arr.forEach((c, g) => { if (c > 0) m += def.own[g]; });   // 옛 코드
```

같은 등급 4개를 합치면 그 등급 개수가 0이 되어 **보유 효과가 통째로 날아간다.**
신품(`own` 2.0)을 전부 합쳐 천품을 만들면 공격력 배율에서 200%p를 잃는다.
"모두 합성" 버튼이 손해일 수 있었다.

영수·신물은 레벨 기준이라 영구였는데, 장비만 이랬다.

### 고친 방식 — 병기보

`s.codex[type][grade]`에 **한 번이라도 손에 쥐었는지**를 적는다. 지워지지 않는다.

- 뽑기에서 나오면 적는다 (`gacha` → `noteCodex`, 첫 획득이면 `first: true`)
- 합성으로 올라가도 적는다 (`merge` → `noteCodex(type, grade + 1)`)
- 보유 효과는 **개수가 아니라 병기보** 기준으로 계산

검증: 범품 4개 보유 → 배율 1.250 → 합성 후 1.670. **합성이 항상 이득이 됐다.**

기존 세이브는 지금 가진 최고 등급까지 전부 기록된 것으로 본다.
합성으로 올라간 것이므로 실제로 거쳐온 게 맞다.

### 도감 완성 효과

```js
CODEX_PER_TYPE = { crit: 0.05 }    // 한 부위 완성마다 치명타 확률 +5%p
CODEX_ALL      = { critDmg: 0.5 }  // 세 부위 모두 완성하면 치명타 피해 +50%p
```

근거: Blade Idle은 무기 4슬롯이 전부 신화 이상이면 치명타 보유효과가 켜진다.
"좋은 옵션 하나"보다 **"빈칸 없이 채우기"**가 먼저가 되는 장치다.

검증: 전부 미기록 → 치명 5.0% / 치명피해 1.50배,
세 부위 완성 → **치명 20.0% / 치명피해 2.00배**.

### 화면

- 부위 제목에 `병기보 5/6`, 완성하면 금색
- 지금 없지만 기록된 등급은 **점선 테두리 + "기록"**
- 보너스 줄이 `보유 +305%` → `병기보 +322%` (46관문 표본 기준, 공격력 ×15.9 → ×16.1)

검증: `node tests/sim.mjs` 12시간 302관문.

## 10. 적용 ④ 아껴 쓰는 자원 — 단계 (2026-10-17, v0.7)

### 있던 구멍

열쇠·패가 **매일 초기화**됐다. 안 쓰면 자정에 사라지니 "아꼈다 쓴다"는 판단 자체가
성립하지 않았다. 어차피 없어지므로 지금 쓰는 게 언제나 정답이었다.

### 고친 것

**1) 쌓인다.** 날마다 지급하되 리셋이 아니라 더하기. 못 들른 날은 한꺼번에(최대 닷새치).

| 자원 | 하루 | 상한 |
|---|---|---|
| 비경 열쇠 | 2 | 10 (닷새치) |
| 토벌 패 | 3 | 9 (사흘치) |
| 결투 패 | 5 | 10 (이틀치) |

상한을 두는 이유: 무한히 모으면 반대로 "영원히 안 쓰는 게 이득"이 된다.

**2) 보상이 계단식으로 뛴다.** 5·10·15·20단계에서 ×1.8.
선형 증가만 있으면 지금 쓰나 나중에 쓰나 같아서 아낄 이유가 없다.

```
 4단계: 한철     62
 5단계: 한철    126   <- x2.03
 9단계: 한철    183
10단계: 한철    356   <- x1.95
14단계: 한철    460
15단계: 한철    874   <- x1.90
```

**3) 소탕은 내가 깬 최고 단계 기준이다** (원래 그랬다).
이제 1+2와 맞물려 **"구간을 넘긴 뒤 몰아서 소탕"**이 정답이 된다.
Blade Idle의 펫 소탕권 판단(터틀 클리어 뒤에 쓴다)과 같은 구조다.

검증: 시뮬레이션에서 비경 도달 단계가 2 → 4로 올랐다.

## 11. 동시 등장 100마리 (2026-10-17, v0.7)

사용자 지정. 5 → 100으로 올리면서 네 가지가 따라왔다.

### ① 젠 속도 기준을 세웠다

APK의 `monsterrespawntime`은 서버값이라 못 본다. 대신 우리 숫자로 기준을 잡았다.

> **기준: 광역기 한 방에 빈 자리를 몇 초 안에 메울 것인가 — 2~3초.**
> 그보다 느리면 광역기 쓰고 들판이 휑하고, 더 빠르면 광역기를 쓴 보람이 없다.

평시 처치 속도는 10마리/45초 = **0.22마리/초**라 고정 간격으로 충분하다.
문제는 광역기다 — 만검귀종(반경 300)은 한 방에 최대 62마리, 뇌정검(210)은 30마리를 지운다.
그래서 고정 간격이 아니라 **빈 자리에 비례**해 채운다.

```js
refillRate(missing, want) = 3 + 34 * (missing / want)
```

| 빈 자리 | 초당 보충 | 다 채우는 데 |
|---|---|---|
| 10 | 6.4 | 1.6초 |
| 30 | 13.2 | 2.3초 |
| 62 | 24.1 | 2.6초 |
| 100 | 37.0 | 2.7초 |

빈 자리 수와 관계없이 **항상 2~3초**로 수렴한다.

### ② 들판을 화면 모양에 맞춰 잡았다

처음엔 반경을 넓게(770) 잡았더니 100마리를 만들어놓고도 화면엔 5~10마리만 보였다.
육각 밀집 기준 한 마리가 `MOB_SEPARATION² × 0.866`을 차지하므로,
n마리가 들어갈 타원 넓이에서 역산한다. 가로 0.55 / 세로 1.35로 눌러 세로 화면에 맞췄다.

결과: **99마리 중 62마리(63%)가 화면 안**.

### ③ 100마리가 동시에 때리면 즉사한다

`MAX_ATTACKERS = 6`. 사거리 안에 몇십이 몰려도 가장 가까운 6명만 때린다.

### ④ 성능

서로 밀어내기가 100마리면 4,950쌍이다. 격자(cell = MOB_SEPARATION)를 만들어
이웃 칸만 본다. 측정: **100마리 tick 0.083ms** — 60fps 예산 16.7ms의 0.5%.

### 가독성 — 여기가 문제다

100마리를 폰 화면(375×812)에 올리면 **화면이 사람으로 메워진다.** 네 가지를 손봤다.

- 체력바를 230px 안의 적만 (전부 달면 주황 막대가 화면을 덮는다)
- 광역 피해 숫자는 6개만 띄우고 나머지는 `14명 적중` 한 줄로 합친다
- 적이 많을수록 조금씩 작게 (12마리 넘으면 최소 0.62배까지)
- 무인은 깊이 정렬에서 빼고 **항상 맨 위**에, 발밑에 노란 고리

그래도 빽빽하다. 마릿수는 결국 취향과 기기 성능의 문제다.

검증: `node tests/sim.mjs` 12시간 349관문 (100마리 적용 전 320).
0.25시간 142관문 (적용 전 59) — 광역기가 훨씬 많이 때려서 초반이 크게 빨라졌다.

### 배포가 반영 안 되던 원인

서비스워커는 "온라인이면 새 파일 먼저"였는데, 그 `fetch`가 **브라우저 HTTP 캐시를
거쳐서** 옛 파일을 그대로 돌려줬다. 네트워크까지 가지도 않았다.

```js
const req = e.request.mode === 'navigate'
  ? e.request
  : new Request(e.request, { cache: 'no-cache' });
```

`navigate` 요청에 init을 덧붙이면 예외가 나므로 그것만 빼놨다. 캐시 이름은 `ifu-v5`.

### 찾은 것 — 의복은 평생 못 산다

성능으로 비교되는 자리에 놓여 있는 게 문제다.

### 고친 것 — 뽑는 행위가 의복도 모아 준다

값을 내리거나 효과를 올리는 쪽은 둘 다 **"뽑기냐 의복이냐"를 계속 고르게 한다.**
그 선택은 플레이어에게 재미가 아니라 손해 계산이다. 그래서 경쟁 자체를 없앴다.

- **병기 소환 레벨 1·2·3·4·5·6·8·10·12·14·16·18**에 의복이 하나씩 온다
  (`OUTFIT_GACHA_LVS`). 뽑기를 돌리면 저절로 모인다
- 특정 의복을 지정하지 않고 **아직 없는 것 중 첫 번째**를 준다 —
  원보로 미리 사 둔 게 있어도 버려지지 않는다
- 원보 구매는 "먼저 갖고 싶으면"으로 남기되 값을 **3분의 1**로 내렸다
  (12종 275,000 → 91,800)
- 영수 소환·신물 발굴로는 안 나온다. 병기 소환만이다

Blade Idle도 코스튬은 뽑기에서 나온다. 원본과도 맞는 방향이다.

### 나머지는 멀쩡하다

혈마의 탑 4.2%가 낮아 보이지만 59층 × 2% = 공격력 +118%이고, 다른 축이
워낙 커서 상대적으로 작게 보일 뿐이다. 유물·영수·심검·무공 연마도
7~17% 구간으로 서로 비슷하다. 결함이 아니다.

## 새 기준선으로 과거 결정을 다시 쟀다 (2026-10-20)

측정 도구를 고쳤으니, 틀린 기준선 위에서 내린 판단을 다시 봤다.
저장소를 통째로 복사해 `data.js`만 바꾼 변종 넷을 동시에 돌렸다.

| 시점 | 기준 | 상태이상 하향 | 장비 초월 끔 | 선택 상자 끔 | 치명 되돌림 |
|---|---:|---:|---:|---:|---:|
| 0.5시간 | 176 | +0 | +0 | +0 | +5 |
| 1시간 | 228 | +0 | +0 | +0 | +7 |
| 2시간 | 269 | −3 | +0 | +0 | +11 |

| 12시간 | 460 | +3 | +1 | +0 | −4 |

### 1. 상태이상 — 수치로는 정할 수 없는 값이었다

출혈 22%/파쇄 1.35와 출혈 12%/파쇄 1.22의 **진행 차이가 사실상 0**이다.
어제 "8시간으로 재니 +3.5%라서 원복했다"고 적었는데, 그 근거가 약했다.

이 값은 **진행 속도로 정할 수 없다.** 체감으로 정하는 게 맞고, 파쇄 ×1.35가
×1.22보다 "걸렸다"는 게 느껴지므로 지금 값을 쓴다.
수치가 근거가 아니라 **수치가 근거가 못 된다는 것**이 근거다.

### 2. 장비 초월 — 8시간에 22관문을 번다

끄면 422 → 400. 실제로 일하고 있다. 어제는 시뮬이 `equipPierceUp`을
부르지도 않아서 기여를 알 수 없었다. 그대로 둔다.

### 3. 선택 상자 — 끄는 게 더 빨랐다. 결함이 있었다

끄면 4시간 +6, 8시간 +3. 추가 자원인데 진행을 돕지 않았다.
파 보니 선택 상자 문제가 아니라 **장신구 장착 로직**이었다.

```
가락지에 범품을 끼고 있는 상태에서 선택 상자 20개를 열면
  → 가방: 보품 15 · 신품 4 · 천품 1
  → 승급 가능? false   등급업 가능? false
```

`autoEquipAcc`가 **비어 있을 때만** 채웠다. 범품을 끼고 있으면 천품이 들어와도
안 바꿨고, 승급은 장착한 것과 **같은 등급**만 재료로 받으므로 그 전부가
잠겨 있었다. 공략의 핵심 판단인 **"가락지만 집중해서 올린다"**가 선택 상자를
넣고도 여전히 성립하지 않았던 것이다.

**고친 것**: 가방에 더 센 게 있으면 갈아낀다. 빼낸 것은 가방으로 돌려 둔다.
**초월은 자리에 남는다** — 한철을 들여 산 것이라 갈아낀다고 날리면 안 된다
(공략에서도 승급과 초월은 별개 축이다).
