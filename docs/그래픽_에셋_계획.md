# 그래픽 업그레이드 — 무엇이 필요하고 어디서 가져오나 (2026-10-20)

무공 이펙트 · 캐릭터 · 전체 UI를 손보기 전에, **지금 뭘로 그리고 있는지**부터
적는다. 여기를 모르면 "3D 모델을 사자"는 결론이 쉽게 나오는데, 그러면 지금
구조를 통째로 버려야 한다.

---

## 0. 지금 상태 — 이미지 파일이 한 장도 없다

| | |
|---|---|
| 이미지 에셋 | **0장** (PWA 아이콘 4장 제외) |
| 그리는 방식 | **Canvas 2D 벡터 드로잉** — `js/battle.js` 1,286줄 |
| 그리기 함수 | 18개 (`drawFighter` `drawJian` `drawHead` `drawWeapon` `iceBlock` …) |
| 렌더 메서드 | 33개 (`drawUnits` `drawEffects` `drawProjectiles` `drawParticles` …) |
| 외부 의존 | **구글 폰트 3종뿐** (Yuji Syuku · Nanum Brush Script · Gowun Batang) |
| UI | `css/style.css` 406줄, 색 토큰 17개 |
| 성능 | 80마리 + 상태이상 한 프레임 **2.24ms** (375×812 / dpr 2 측정) |

즉 **사람도 검도 장판도 전부 코드로 그린다.** 이게 장점이자 한계다.
장점은 용량 0 · 어떤 해상도에도 선명 · 색을 코드로 바꿀 수 있다는 것,
한계는 **그림체가 단순한 도형 수준에서 못 올라간다**는 것.

### 지금 그려지는 것들

- **캐릭터**: 무인 1 + 적 생김새 11종 (`look` 정의: 무복 색·머리·무기·기운·후광)
- **무공**: 14종, 동작 8가지 — `aoe` `single` `chain` `dash` `blink` `field` `tornado` `pierce`
- **무공 효과 연출**: 8종만 따로 있음 (`slash` `thunder` `frost` `meteor` `rage` `gale` `midas` `heal`)
- **상태이상**: 빙결(얼음 덩어리) + 둔화·출혈·파쇄(작은 점 3개)
- **등급**: 6단계 색 / **경지**: 10단계 / **재화**: 은자·원보·비급·한철·영수밥·신물조각

## 1. 먼저 정할 것 — 세 갈래 중 하나

이게 가장 중요한 결정이다. 뒤에 나오는 에셋 목록이 전부 여기에 달려 있다.

### A. 벡터 유지 + 다듬기

지금 코드를 그대로 두고 **그리기 함수만 고급화**한다. 그라디언트·그림자·파티클·
블렌드 모드를 더 쓰고, 이펙트를 늘린다.

- **필요 에셋**: 거의 없음 (노이즈 텍스처 1~2장 정도)
- **작업**: 전부 코드
- **비용**: 0원
- **한계**: 그림체가 "잘 그린 도형"을 못 넘는다
- **위험**: 없음

### B. 2D 스프라이트로 교체 ← **추천**

캐릭터·이펙트를 **PNG 스프라이트 시트**로 바꾸고 `drawImage`로 붙인다.
배경·UI도 이미지로.

- **필요 에셋**: 아래 2절 목록 (대략 **120~260장**)
- **작업**: `drawFighter` → `drawImage` 교체. **이미 스프라이트 캐시 구조가 있다**
  (오늘 넣은 `fighterSprite`) — 캐시가 굽던 자리를 PNG로 바꾸면 끝
- **비용**: 무료 에셋이면 0원, 유료 팩이면 3~15만원, 생성형이면 구독료
- **한계**: 해상도 고정(2x 준비 필요), 용량 증가
- **위험**: 중간. 색 변주(등급별 색)를 코드로 못 하니 **틴트(tint) 처리**가 필요

### C. 3D (three.js)

- **필요 에셋**: `.glb` 모델 + 애니메이션 + 텍스처
- **작업**: `battle.js` **전면 재작성**
- **비용**: 모델당 2~20만원 또는 직접 제작
- **위험**: **높다.** 80마리 동시 렌더를 모바일에서 60fps로 돌리려면 인스턴싱·
  LOD·그림자 끄기까지 해야 한다. 지금 2.24ms인 프레임이 10배 이상 뛴다
- **판단**: 지금 단계에서는 **안 하는 게 맞다**

> **추천: B.** 이유는 셋이다.
> ① 오늘 넣은 스프라이트 캐시가 이미 "한 장 구워서 붙인다" 구조라 교체 지점이 명확하다
> ② 가장 크게 달라 보이는 건 **캐릭터 그림체**인데 그건 2D로 충분하다
> ③ 3D는 성능·작업량·되돌리기 비용이 전부 한 자릿수 더 크다
>
> 다만 **A를 먼저 하루 해보고 B로 넘어가는 것**도 좋다. 이펙트는 코드가 더 유연하다.

## 2. 필요한 에셋 목록 (B 기준)

### 2-1. 캐릭터 — 가장 먼저, 가장 크게 달라 보인다

| 항목 | 수량 | 규격 | 비고 |
|---|---|---|---|
| 무인(주인공) | 1종 × 4동작 × 8프레임 | 256×256 @2x | 대기·걷기·공격·피격 |
| 졸개 | 11종 × 2동작 × 6프레임 | 192×192 @2x | 대기·걷기 (공격은 공용 가능) |
| 관문지기(보스) | 구역당 1종, 8종 | 384×384 @2x | 대기·공격 |
| 심마 / 그림자 | 2종 | 256×256 @2x | 시련·그림자 무림용 |

- **합계 약 100~160장** (시트로 묶으면 파일 20장 내외)
- **포맷**: PNG(투명) 또는 WebP. 시트는 가로 배열 + JSON 좌표
- **방향**: 한쪽만 그리고 `ctx.scale(-1,1)`로 뒤집는다 (지금도 그렇게 한다)
- ⚠️ **시점 주의**: 우리 화면은 **위에서 내려다보는 평면에 인물을 세워 그리는** 방식이다
  (`FIELD_SQUASH = 0.62`). 정측면 도트는 안 맞고, **살짝 내려다본 3/4 뷰**가 맞는다

### 2-2. 무공 이펙트 — 14종, 동작 8가지

동작별로 필요한 게 다르다.

| 동작 | 해당 무공 | 필요한 것 |
|---|---|---|
| `aoe` | 선풍검 · 뇌정검 · 만검귀종 | 원형 충격파 시트 (8~12프레임) × 3 |
| `single` | 빙백신장 | 단일 타격 + 얼음 시트 |
| `chain` | 연환벽력 | 번개 줄기 1장 (이어 그림) + 분기 섬광 |
| `dash` | 발도돌격 | 잔상 띠 + 베기 궤적 |
| `blink` | 축지참 | 사라짐/나타남 2종 |
| `field` | 매화검진 | 바닥 장판 (루프 12프레임) |
| `tornado` | 선풍장 | 회오리 (루프 8프레임) |
| `pierce` | 일자검기 | 직선 관통 띠 |
| 버프 3종 | 혈마해방 · 질풍보 · 천금수 | 발밑 고리 + 상승 입자 |
| 회복 | 운기조식 | 치유 고리 |

- **합계 약 14세트, 120~180프레임**
- **규격**: 256×256 또는 512×512 @2x, 투명 PNG
- **블렌드**: `globalCompositeOperation = 'lighter'`로 더하기 합성 — 검은 배경이 투명처럼 처리됨
- 💡 **대안**: 이펙트는 **코드가 더 낫다.** 색·크기·지속시간을 데이터로 바꿀 수 있고
  용량이 0이다. 캐릭터만 이미지로 가고 **이펙트는 A(벡터)로 남기는 혼합**을 권한다

### 2-3. 상태이상 아이콘

| | 수량 | 규격 |
|---|---|---|
| 빙결 · 둔화 · 출혈 · 파쇄 | 4종 | 64×64 @2x |

지금은 색 점 3개다. 작은 아이콘으로 바꾸면 읽기 쉬워진다.

### 2-4. UI

| 항목 | 수량 | 비고 |
|---|---|---|
| 탭 아이콘 | 6종 (영수·비경·무림·수련·병기·무공) | 48×48 @2x |
| 서브탭 아이콘 | 17종 | 32×32 @2x |
| 재화 아이콘 | 6종 (은자·원보·비급·한철·영수밥·신물조각) | 48×48 @2x |
| 능력치 아이콘 | 10종 (공격력·체력·치명·치명피해·속도·은자·경험치·두목·방치·두목시간) | 32×32 @2x |

### 2-5. 배경

| 항목 | 수량 | 규격 |
|---|---|---|

## 4. 작업 순서 — AI 슬롭을 피하는 6단계

`AI-ARCHIVE/UX기획/2026-09-02-클로드-디자인.md`의 방법을 그대로 쓴다.
**매직 프롬프트가 아니라, AI가 대신 내릴 결정을 내가 통제하는 절차**다.

1. **REFERENCE — 취향 보드부터**
   프롬프트를 바로 치지 않는다. 레퍼런스 **2~5개**를 모으고 *각각에서 뭘 가져올지*를
   명시한다. "A에서 색, B에서 캐릭터 비율, C에서 UI 배치".
   레퍼런스 소스: Pinterest(무협 일러스트), itch.io(2D 게임 에셋), Awwwards, Lapa Ninja.
   ⚠️ **지금 게임 스크린샷도 같이 올린다.** 그래야 실제 화면 기준으로 디자인한다

2. **EXPLORE — "의미 있게 다른 6개"**
   *"같은 레이아웃의 색상 변형 6개가 아니라, 의미 있게 다른 6개를."*
   탐색할 축을 못 박는다: 캐릭터 비율(2.5등신 vs 6등신), 선 두께, 채도,
   배경 밀도, UI 밀도(빽빽 vs 여백).
   *"레퍼런스를 영감으로 쓰되 누구의 것도 재현하지 마라. 평균 내지 말고
   하나의 일관된 방향으로 종합하라."*

3. **SYNTHESIZE — 하나를 고르지 않는다**
   6개 중 꼭 드는 게 없는 게 정상이다. 좋은 **조각마다** 코멘트를 붙이고
   *"코멘트 붙은 요소들을 결합한 새 옵션을 만들어라."*

4. **EXPLODE — tweaks로 세부 폭발**
   방향을 확정한 뒤 그 **안에서** 변형을 판다. 버튼 채움·카드 스타일·간격·
   강조색·테두리. *"이런 반복을 코드로 하면 영원히 걸린다."*
   > **원칙: 큰 것 하나, 나머지는 전부 미묘하게.**
   > 우리 게임의 "시그니처" 후보 — 관문지기를 넘는 순간의 연출, 회귀할 때의 전환

5. **EXPAND — 한 화면을 기준으로 나머지**
   전투 화면을 확정하면 그게 **visual source of truth**가 된다.
   "이걸 기준으로 병기·무공·수련 탭을 만들어줘"

6. **BUILD — 코드로**
   zip으로 받아 폴더째 넘기는 게 안전하다(핸드오프 프롬프트는 문제가 잦다).

### 모델을 어디에 쓸까

아카이브의 실전 비교(`인사이트/2026-09-14-Fable-vs-Astra-실전비교.md`):

## 5. 넘어가기 전에 확인할 것

### 5-1. 성능 예산

지금 80마리 + 상태이상이 **한 프레임 2.24ms**다(375×812 / dpr 2).
폰이 4~6배 느리면 9~13.5ms. **16.7ms 안에 들어와야 60fps다.**

이미지로 바꾸면 보통 더 빨라지지만(벡터 경로 → 단일 blit), **주의할 것**:
- 스프라이트 시트가 크면 **GPU 텍스처 업로드**가 첫 프레임을 끊는다 → 미리 로드
- 등급별 색 변주를 매 프레임 틴트하면 느려진다 → **구워서 캐시** (오늘 만든 구조 재사용)
- 이미지 총 용량이 커지면 **첫 로딩**이 길어진다

### 5-2. 용량 예산

지금 전체가 **코드 몇십 KB + 폰트**다. 목표를 정하고 가야 한다.

| 항목 | 권장 상한 |
|---|---|
| 캐릭터 시트 전부 | 1.5MB |
| 이펙트 전부 | 1MB |
| UI·아이콘 | 300KB (SVG면 훨씬 작다) |
| 배경 | 1.5MB |
| **합계** | **4MB 이하** |

- **WebP**를 쓴다 (PNG 대비 30~50% 작다). 모든 최신 브라우저가 지원
- 구역 배경은 **지연 로딩** — 그 구역에 들어갈 때 받는다
- `sw.js` 캐시 목록에 에셋을 넣어야 두 번째 방문이 빠르다

### 5-3. 되돌릴 수 있게

벡터 그리기 코드를 **지우지 말고** 남겨 둔다.
`USE_SPRITES` 같은 스위치를 두고, 이미지가 없으면 벡터로 떨어지게.
에셋 작업이 중간에 멈춰도 게임이 돌아간다.
