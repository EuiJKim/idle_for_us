# 回歸 우리끼리 회귀무림

친구 5명이서 같이 하는 무협 회귀 방치형 RPG. 수묵화풍 그림은 모두 코드로 직접 그린다(외부 그림 없음). 웹앱(PWA)이라 **안드로이드와 아이폰 모두** 홈 화면에 추가해서 앱처럼 쓸 수 있다.

**▶ 플레이: https://euijkim.github.io/idle_for_us/**

## 폰에 설치하기

- **아이폰:** 사파리로 링크 열기 → 아래 공유 버튼 → **홈 화면에 추가**
- **안드로이드:** 크롬으로 링크 열기 → 오른쪽 위 ⋮ → **홈 화면에 추가** (또는 **앱 설치**)

홈 화면 아이콘으로 열면 주소창 없이 전체화면으로 열리고, 새 버전은 다시 열 때 자동으로 반영된다.

## 개발

빌드 과정 없는 순수 HTML/JS(ES 모듈)다.

```bash
npx http-server -p 8123 -s -c-1 .     # http://localhost:8123
node tests/sim.mjs 24                  # 밸런스 시뮬레이션 (24시간 쉬지 않고 플레이 시 도달 스테이지)
```

```
js/data.js      수치·세계관 테이블 (경지, 무공, 지역별 적 외형, 회귀 …) (강화 비용, 몬스터 체력, 장비 효과 …) ← 밸런스는 여기만 고치면 된다
js/game.js      게임 규칙 (DOM 없음, Node에서도 동작)
js/battle.js    수묵화 전투 화면 (무인·배경·초식 이펙트를 모두 캔버스로 그림)
js/ui/*.js      하단 탭 화면 (성장·장비·스킬·동료·던전·친구, 미션)
                탭 안은 common.js의 subTabs()로 다시 나뉜다 — 아래 '창 구조' 참고
js/net.js       Firebase (익명 로그인, 프로필, 길드, 채팅, 레이드)
js/main.js      시작, 저장, 게임 루프, 방치 보상, 설정
sw.js           오프라인 캐시 (파일을 바꾸면 CACHE 이름을 올릴 것)
tools/gallery.html  모든 경지·적 무인을 한 장에 그려 보는 도감 (그림 확인용)
tools/icon.html     앱 아이콘 생성 페이지
```

### 창 구조

탭 하나에 카드를 세로로 쌓지 않는다. 모든 탭은 `subTabs()`로 다시 나뉜다.

| 탭 | 하위 탭 |
|---|---|
| 수련 | 수련 · 레벨 · 경지 · 문파 · 회귀 |
| 병기 | 병기 · 장신구 · 심검 |
| 무공 | 무공 · 패시브 |
| 영수 | 영수 · 신물 · 인물도감 · 의복 |
| 비경 | 수련터 · 광맥 · 탑 · 탐색 |
| 무림 | 서열 · 비무대 · 문파 · 그림자 · 창고 |
| 의뢰(모달) | 오늘 · 의뢰 · 업적 · 상점 |

**쓰는 자원은 창 머리에 띄운다.** 화면이 `res: ['books']`처럼 올리면
`main.js`의 `panelRes()`가 창 머리 자원칸을 그 자원으로 바꾼다.
올릴 수 있는 이름은 `js/ui/common.js`의 `RES_DEFS`에 있는 것뿐이고,
없는 이름을 올리면 조용히 사라지므로 `tests/wiring.mjs` 6절이 본다.

아이콘은 `js/icons.js`의 `KINDS`가 전부다. **그림이 오기 전에 자리를
달라고 하면 줄을 세워 두었다가 와서 붙인다** — 들판 무공 바는 시작하자마자
한 번 만들어져서, 줄을 안 세우던 때는 창 안에만 그림이 뜨고 들판에는
글자가 남았다.

긴 목록은 **상태별로 묶는다** — 무공은 장착 중·쓸 수 있음·잠김,
영수는 데려간·가진·아직 없는 것으로 나뉜다.

### 수련 차수

수련 **열여섯 축**에는 **상한이 없다.** 한 차수를 다 채우면 다음 차수가 열린다 —
혈도 찌르기 → 극혈도 → 현혈도 → 천혈도 → … → 혈도 9중. 끝이 없다.
상한이 있는 통계(치명 확률 `CRIT_CAP`, 공격 속도 `SPEED_CAP`)는 다음 차수에서
**상한 없는 짝 통계로 갈아탄다**(치명 확률 → 치명 피해, 공격 속도 → 연격).
곱하기 축(외공·내공)은 증가율을 올리면 초지수가 되어 터지므로, 2차부터
덤 통계를 하나 얹는다. 자세한 건 `js/data.js`의 `UP_TIER_GAIN` 둘레.

**무공에도 같은 차수가 있다** — 50레벨마다 선풍검 → 극선풍검 → 현선풍검으로
이름이 바뀌고 배율이 `SKILL_TIER_GAIN`배 곱해진다. 배율을 작게 잡은 이유는
무공 레벨이 관문의 0.18배라 관문당 x1.002밖에 안 되기 때문이다 — 네 곡선을
흔들지 않는 크기여야 한다.

### 문파

전직하면 바뀌는 것이 셋이다.

1. **전용 무공 셋** — 일반 칸을 먹지 않고 문파 칸에 따로 들어간다.
   1차는 전직과 동시에, 2차·3차는 `JOB_SKILL_OPEN`(260 · 420관문)에 열린다.
2. **문파 특성** — `JOB_TRAITS`. **쓰는 모든 무공에** 그 문파의 기운이 실린다.
   혈천도마면 뇌정검에도 출혈이 붙고, 마불이면 무공을 쓸 때마다 체력이 찬다.
   맛보기(`taste`)로는 안 붙는다 — 그러면 전직할 이유가 없다.
3. **들판 빛깔** — 무공 사건에 `job`을 실어 보내 `skillEffect`가 그 문파 색으로
   한 겹 더 그린다. 특성의 `fx` 이름이 battle.js의 kind로 이어지는지는
   `tests/wiring.mjs` 6절이 본다 — 오타 하나면 그 문파만 조용히 아무 빛도 안 난다.

특성이 **실제로 전투에 들어가는지**는 `tests/check.mjs` 27절이 여덟 개를 하나씩
돌려 본다. 주고도 안 읽는 자리를 만들지 않으려는 것.

### 무공 연계

무공이 서른여덟인데 고르는 기준이 "센 것 여덟"뿐이면 칸이 여덟일 이유가 없다.

무공마다 **남기는 기운**과 **먹는 기운**이 있다(`SKILL_QI`, 여섯 가지:
인 雷 한 풍 독 기). 앞 무공이 남긴 기운을 다음 무공이 `COMBO_SEC` 안에
먹으면 연계가 터져 피해가 `comboMult()`배, 상태이상이 `COMBO_CC`배가 된다.
연달아 이으면 더 커지고 `COMBO_STREAK_MAX`에서 멈춘다.

**고리가 막히면 안 된다** — 여섯 기운이 모두 남겨지고 모두 먹혀야 하고,
자기가 남긴 걸 자기가 먹는 무공이 있으면 연타만으로 계속 터진다.
`tests/check.mjs` 29절이 둘 다 본다. 자동 시전도 이어지는 무공을 먼저 고른다.

### 공적

관문지기를 넘으면 쌓인다(`bossMerit`). 쓰는 곳은 둘뿐이다.

- **특성 단련** — 문파 특성이 레벨만큼 세진다(`traitScale`). 끝이 없다.
  **문파마다 따로 쌓인다** — 갈아타면 들인 공적을 두고 간다.
- **문파 교체** — 처음 드는 건 공짜, 바꿀 때마다 값이 오른다(`jobSwitchCost`).
  거쳐 본 문파로 돌아가는 건 절반이다.

갈아타는 진짜 값은 공적이 아니라 '그 문파에 들인 단련'이다. 전에는 공짜라
상황마다 갈아타는 게 늘 이득이었고, 그래서 고르는 게 고르는 일이 아니었다.

### 회귀

**배수는 곱하기다** — `regressMult(pt) = REGRESS_BASE ^ pt`. 더하기로 두면
뒤로 갈수록 반드시 손해가 된다. 전에 `1 + 0.16 x pt`였는데, 관문 600에서
x18.6 · 900에서 x28.2였다. 300관문을 더 가는 데 드는 힘은 1.085^300 = 2e11배인데
돌려받는 건 1.5배 — 그래서 여덟 시간에 회귀가 0~1번밖에 안 터졌고
두 시간을 넘기면 관문이 꺾였다.

권하는 기준도 '포인트 수'가 아니라 **몇 배 세지는가**(`REGRESS_WORTH_MULT`)다.
포인트로 재면 관문 눈금을 바꿀 때마다 같이 틀어진다 — 실제로 한 번 틀어져
일주일 시뮬에서 회귀가 한 번도 안 터진 적이 있다.

재 보면 8시간 877 → **1416관문**, 12시간 1113 → **1828관문**.

### 방치

'방치형'인데 자리를 비우면 관문이 안 밀렸다. 돌아오면 은자·경험치만 쥐여
주고 관문은 그대로였다 — 켜 놓고 기다린다는 말이 성립하지 않았다.

| 어떻게 비웠나 | 무슨 일이 일어나나 |
|---|---|
| 앱을 껐다 | 은자·경험치만 (`offlineReward(now, false)`) |
| 켜 둔 채 화면만 꺼졌다 | **관문도 민다** — 싸우고 있던 셈이다 |
| 들판의 「수련」이 켜져 있다 | 제자리에서 벌기만 한다 |

가른 자리는 `js/main.js`의 `hiddenAt`이다. 가려질 때 적어 두고, 돌아올 때
그 값이 있으면 켜 둔 채였다고 본다.

**얼마나 빨리 미는지는 추측하지 않고 잰다.** 처음엔 평타로 어림했는데
무공·영수를 빼먹어서 **274배가 느렸다**(어림 7690초 vs 실제 28초).
이제 관문을 깰 때마다 걸린 시간을 `s.pace`에 섞어 두고 그 값을 쓴다.
서 있는 동안 적도 세지므로 관문마다 `OFFLINE_PACE_DRIFT`씩 길어진다 —
이게 '너무 멀리 가는 것'을 막는 유일한 빗장이다. 여기에 '몇 대 버티나'를
따로 걸었더니 몇 시간을 비워도 스물세 관문에서 딱 멈췄다(두 번 센 것).

`keepAwake`(화면 안 꺼지게)와 `autoTrain`(번 은자를 수련에 붓기)은 설정에서
끈다. 둘 다 기본은 켜짐이다.

### 새 판이 기기에 들어가는 길

배포는 멀쩡한데 **기기에만 안 들어간** 일이 실제로 났다. 눈으로는 절대 못 잡는
종류라 길을 세 겹으로 두고 `tests/wiring.mjs` 8절이 전부 본다.

1. `sw.js` 설치가 **한 장씩**이다(`allSettled`). `addAll`은 한 장만 404여도
   통째로 실패하고, 그러면 새 워커가 영영 설치되지 않아 기기가 옛 판에 묶인다.
2. `js/main.js`의 `checkBuild()`가 서버의 `sw.js`에 적힌 판을 **직접 읽어**
   지금 판과 견준다. 워커가 꼬여 있어도 이건 그냥 fetch라 늘 맞는 답을 준다.
   다르면 화면 위에 띠를 띄운다. 열어 둔 채로 며칠 지나는 사람을 위해
   돌아올 때마다(`visibilitychange`)와 10분마다 다시 본다.
3. 설정에 **새로 받기**가 있다. 워커와 캐시를 통째로 버리고 주소에 표시를
   붙여 다시 받는다 — 이미 꼬인 기기를 손으로 푸는 유일한 길이다.
   세이브는 localStorage라 안 지워진다.

판을 올릴 때는 `sw.js`의 `CACHE`와 `js/data.js`의 `BUILD`를 **같이** 올린다.
다르면 알림이 엉뚱하게 계속 뜬다(wiring 3절·8절이 본다).

### 밸런스를 고칠 때

**네 곡선이 같은 줄에 있어야 한다** — 적 체력 · 적 공격 · 내 DPS · 내 체력.

| 어긋나면 | 무슨 일이 나는가 |
|---|---|
| 내 DPS > 적 체력 | 적이 때려 보지도 못하고 죽는다. 체력 축이 통째로 죽는다 |
| 적 체력 > 내 DPS | 관문이 안 넘어간다. 벽 앞에서 멈춘다 |
| 적 공격 > 내 체력 | 어느 관문부터 손도 못 쓰고 즉사한다 |
| 적 공격 < 내 체력 | 안 죽는 캐릭터가 된다 |

넷 다 실제로 겪었다. 상수만 보고는 못 안다 — 경제(은자·비급·한철)가 성장
속도를 정하므로 **반드시 재야 한다.**

```bash
node tests/fourcurves.mjs 3     # 네 곡선의 비율 + 실제로 초당 몇 %를 맞는지
node tests/sim.mjs 9            # 시간대별 도달 관문 + 자원이 마르는지
```

목표: 네 비율이 서로 1% 안, **초당 받는 피해 1~15%**, 초당 맞는 횟수 > 1.

자원 수입은 전부 관문에 **지수**다(`stageBooks` · `stageStones` · `stageFood` ·
`stageShards`). 쓰는 쪽이 전부 지수라 선형으로 두면 몇 시간 만에 말라붙는다.
고정 보상은 `scaleReward(r, 관문)`으로 '몇 관문치'로 적는다.
